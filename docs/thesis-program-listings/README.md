# Thesis program-listing package

Read [AUDIT.md](AUDIT.md) first, then use [PYTHON_CODE_LISTINGS.md](PYTHON_CODE_LISTINGS.md) for the thesis appendix. It contains 51 focused listings, each with the requested source, symbol, description, exact code, actual-output fence and final inventory. Model listings describe the current **provisional Prophet + XGBoost implementation**; they do not establish approved final methodology.

Application code was reconciled to the all-seven modeling rule, and the source excerpts and verification evidence were regenerated. The source is the current working tree, including any pre-existing edits, not an assumed pristine checkout. Exact source spans and SHA-256 values are in [listing-manifest.json](listing-manifest.json).

## Evidence

- [pytest-verified.txt](evidence/pytest-verified.txt): 51 passed, 1 skipped, 5 Dash DataTable deprecation warnings.
- [canonical-verified.txt](evidence/canonical-verified.txt): real Prophet/XGBoost execution on the repository canonical CSV, in a temporary SQLite database.
- [canonical-verification.json](evidence/canonical-verification.json): seven completed hybrids, 84 stored monthly forecasts, complete ranking and seven holdout evaluations; all provisional.
- [canonical-verification.html](evidence/canonical-verification.html): report actually generated by that run. Open locally to inspect the interactive chart or print the HTML.
- [probe-outputs.txt](evidence/probe-outputs.txt): exact printed outputs of canonical CSV/XLSX loading, status/date probes, metric/combination examples, and selections from the real-run JSON.
- [pytest.txt](evidence/pytest.txt) and [canonical-run.txt](evidence/canonical-run.txt): initial sandbox attempts, retained to disclose temporary-directory permission failures. They are not the successful verification evidence.

The unit tests use synthetic fixtures and some injected workflows. The canonical verifier uses actual model libraries with no substitute model. Neither run uses the active application database. The cloud test is deliberately disabled for this local audit: a SKIPPED status does not demonstrate Supabase availability or persistence. No cloud credentials or deployment were inspected or changed. The existing headless browser workflow was rerun; see browser-verified.txt for the actual outcome.

- [browser-verified.txt](evidence/browser-verified.txt): separate real-browser workflow verification.
- [synthetic-verified.txt](evidence/synthetic-verified.txt) and [synthetic-verification.json](evidence/synthetic-verification.json): all seven candidates attempted on a two-block synthetic upload; two hybrid completions, five explicit insufficient-history outcomes, 24 monthly values and unavailable Top Five.
- [package-validation.json](evidence/package-validation.json): exact source spans/hashes, document links, active terminology scan and verified-output checks.

## Reproduction

From the repository root, using its existing environment:

```powershell
.venv/Scripts/python.exe docs/thesis-program-listings/verify_repository.py
```

The runner captures the tests, canonical and synthetic `tools/verify_prototype.py` executions, and the existing headless Edge browser workflow, then regenerates and validates the listings. It clears `PROTOTYPE_CONFIG_PATH` in child processes to use explicit repository defaults and removes `TEST_SUPABASE_DATABASE_URL` in those processes to avoid live cloud writes. It does not edit environment settings permanently. The actual audit executed these commands separately and captured their outputs before consolidating them in this runner.

To re-extract source and re-run lightweight output probes using the already captured model evidence:

```powershell
.venv/Scripts/python.exe docs/thesis-program-listings/build_listings.py
```

Do not regenerate against changed application code and claim that older test/model outputs verify the new code. Re-run verification after implementation changes. Numerical model outputs can vary with package/platform versions; the captured values document this run. Raw model-log clock timestamps are retained unchanged; the audit date uses Asia/Manila client context.
